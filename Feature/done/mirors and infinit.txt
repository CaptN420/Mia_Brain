# TASK — Implement a Mathematical Mirror / Reflection Layer in the Agentic Architecture

You are working on an experimental multi-agent AI architecture.

I want you to investigate and implement a **Mirror / Reflection Layer** based on a mathematical transformation concept.

## 1. Core idea

Introduce a dedicated agent called:

`MirrorAgent`

Its role is NOT to simply generate another answer.

Its role is to:

1. receive the output of another reasoning agent;
2. transform the reasoning through a defined mathematical "mirror";
3. search for an alternative interpretation;
4. detect contradictions, symmetry, inversions and hidden assumptions;
5. return the transformed reasoning to the Orchestrator;
6. allow the Orchestrator to compare the original reasoning with the mirrored reasoning.

Conceptually:

```text
Input
  ↓
Worker / Thinker
  ↓
Original reasoning
  ↓
MirrorAgent
  ↓
Mirrored reasoning
  ↓
Orchestrator / Second Thinker
  ↓
Comparison
  ↓
Final decision
```

The MirrorAgent should therefore function as a **divergence / verification agent**, not as another generic worker.

Use the experimental set:


For example, support a configurable mirror function:

```python
mirror(x, center)
```


This gives a mathematically defined reflection around `c`.

The system must allow the mirror center to be configurable.

Do NOT assume that the numbers 1, 2, 6, 8 and 10 have a universally recognized mathematical "mirror" meaning.

Instead, test their relationships and record the results.

# 6. Mirror operation for AI reasoning

The most important implementation is the reasoning mirror.

Given:

```text
Original hypothesis H
```

generate:

```text
Mirror(H)
```

The MirrorAgent should ask questions such as:

```text
What if the main assumption is reversed?

What information is missing?

What happens if the relationship is inverted?

What is the opposite interpretation?

What remains invariant?

What changes?

Is there a contradiction?

Does another mathematical representation produce the same result?

Could the original reasoning be overconfident?
```

The MirrorAgent should actively attempt to produce a **constructive disagreement**.

This is important because simple self-reflection can sometimes reinforce the original reasoning instead of discovering an error.

# 7. Orchestrator integration

The Orchestrator / Second Thinker must receive both:

```text
ORIGINAL
```

and

```text
MIRROR
```

Example:

```json
{
    "original": {...},
    "mirror": {...},
    "comparison": {...}
}
```

The Orchestrator then decides:

```text
KEEP_ORIGINAL
KEEP_MIRROR
MERGE
REQUEST_REANALYSIS
REJECT_BOTH
```

The Orchestrator must NOT blindly prefer the MirrorAgent.

The goal is:

```text
divergence → comparison → verification → decision
```

not:

```text
worker → mirror → automatically trust mirror
```

# 8. Add a mathematical validation layer

Create a component such as:

```text
MathValidator
```

Its job is to classify every transformation:

```text
VALID_STANDARD_MATH
VALID_UNDER_SPECIFIC_FORMALISM
EXPERIMENTAL_RULE
UNDEFINED
CONTRADICTORY
REQUIRES_NUMERICAL_TEST
```

This is extremely important.

The architecture should never confuse an experimental computational rule with established mathematics.

For example:

```text
∞ / 12 = ∞
```

should be tagged according to the mathematical framework being used rather than blindly declared true.
